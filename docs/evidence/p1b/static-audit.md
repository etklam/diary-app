SQLCipher requires the config plugin, prebuild and a new development binary. Native asynchronous random bytes will supply the database key.
- One native session and generated client already exist. Extend the owner capability with by-date and explicit single-attempt writes; do not construct another session. The shared `NO_AUTOMATIC_SESSION_RETRY_HEADER: 1` bypasses mutation replay on 401. Auth recovery can verify/refresh separately without replaying the POST.
- By-date returns HTTP 200 with a direct DiaryResponse or null. POST returns 201 for create and append. `appendToToday` operates on the submitted date, not the current day. The API serializes owner/date create and append with an advisory transaction lock.
- Append content is exactly existing content + `\n\n---\n\n` + submitted content. Existing title/source/createdAt remain unchanged. Tags use ordered set union; stock associations use normalized distinct symbols and server ordering. A non-append occupied date returns 409 `DIARY_ALREADY_EXISTS`.
- The existing vendored domain artifact exports `calendarDateInTimezone` and `deriveQuickTitle`; add that artifact as a dependency without repacking. Shared request/response schemas provide normalization and validation.
- Current generated Android app permits backups. Draft DB and SecureStore key must be excluded from backup/device transfer together. Missing keys or unreadable encrypted databases must fail closed without recreation/deletion.
- Plan: one SQLCipher database, a random 256-bit key in SecureStore, parameterized owner/scope rows containing schema-validated drafts and pending attempts. Debounced autosave and ordered writes flush on background/navigation. One controller per owner capability survives composer unmounts, with synchronous owner invalidation.
- Before POST, validate, read baseline, durably record exact payload/baseline, then send once. Persisted saving restores as uncertain. Reconcile using GET only: exact canonical create or exact baseline-plus-append result confirms; unchanged baseline permits an explicit later save; any other result remains ambiguous. No substring matching or local idempotency claim.
